## Latar Belakang

Di setiap acara, entah pernikahan, wisuda, ulang tahun, atau acara kantor, foto terbaik justru sering ada di HP para tamu, dan hampir tidak pernah sampai ke tuan rumah. Mengumpulkannya lewat grup chat membuat kualitas foto turun dan berkas tercecer.

**Memoir** menyelesaikan masalah itu: host membuat event, mencetak QR code di meja tamu, lalu tamu cukup scan dan mengunggah foto dari browser HP, **tanpa install aplikasi dan tanpa membuat akun**. Semua foto masuk ke satu galeri, dan host bisa langsung menyusunnya menjadi album siap cetak.

## Alur Utama

| Siapa | Yang dilakukan |
|---|---|
| **Host** | Membuat event, memilih tema, mencetak QR code / kartu meja, memoderasi foto, mengunduh semua foto (ZIP), mendesain album |
| **Tamu** | Scan QR → memotret dengan kamera di halaman (dengan frame) atau memilih dari galeri → foto langsung terunggah |
| **Owner / Admin** | Mengelola paket, menyetujui pembayaran, membantu menjalankan event pelanggan |

## Fitur Unggulan

- **Kamera di halaman**: tamu bisa memotret beberapa foto sekaligus dengan 8 pilihan frame; otomatis beralih ke kamera bawaan HP bila akses kamera tidak tersedia.
- **Album studio**: menyusun semua foto ke halaman album A4 lanskap dengan 8 template (Classic, Polaroid, Minimal, Editorial, Film, Scrapbook, Noir, Vintage). Mesin layout mencocokkan tata letak halaman dengan orientasi foto; host bisa drag & drop foto, ganti layout, gabung/pisah halaman, dan menambah caption.
- **QR code bergaya & kartu meja**: 5 gaya QR (dengan opsi logo/inisial di tengah), unduh PNG/SVG, dan 6 desain kartu meja siap cetak.
- **Kontrol host**: moderasi foto sebelum tampil, waktu reveal galeri, buka/tutup unggahan, tema warna dan pola halaman tamu.
- **Paket & pembayaran**: tiga paket (Basic, Premium, Unlimited) dengan batas jumlah tamu dan foto per tamu; pembayaran manual via transfer/QRIS yang disetujui owner.

## Arsitektur

```
Browser tamu ──(presigned PUT)──▶ Object storage (MinIO / Cloudflare R2)
     │                                   ▲
     ▼                                   │
Frontend (Next.js) ──▶ Backend API (Express + Prisma) ──▶ PostgreSQL
```

Foto diunggah **langsung dari browser ke object storage** lewat presigned URL, sehingga API tidak menjadi bottleneck. API kemudian memverifikasi berkas dan membuat thumbnail.

| Layer | Pilihan |
|---|---|
| Frontend | Next.js 16 (App Router) + React 19 + TypeScript |
| Backend | Node.js + Express + TypeScript, Prisma ORM |
| Database | PostgreSQL |
| Storage | S3-compatible: MinIO (lokal), Cloudflare R2 (produksi) |
| Media | `sharp` (thumbnail WebP 480px), `qrcode`, `archiver` (ZIP streaming) |
| Deploy | Vercel (frontend + API), Postgres terkelola, Cloudflare R2; Docker Compose untuk lokal |

## Keamanan Sejak Desain

Dengan latar belakang di bidang security, saya memperlakukan setiap unggahan dari publik sebagai input yang tidak dipercaya:

- **Validasi isi berkas, bukan ekstensi**: tipe file dicek dari *magic bytes* (JPEG/PNG/WebP/HEIC).
- **Privasi foto**: metadata EXIF (termasuk lokasi GPS) dihapus saat thumbnail dibuat.
- **RBAC dicek ke database di setiap request**: peran OWNER, ADMIN, dan EVENT_ADMIN tidak hanya dipercaya dari isi token JWT.
- **Rate limiting per IP** sebagai lapisan pertahanan untuk endpoint publik tamu.
- **Link unduhan bertanda tangan** yang kedaluwarsa dalam 5 menit untuk ekspor ZIP.

## Kualitas & CI/CD

- Backend diuji dengan **Vitest + Supertest** dengan target coverage **≥80%**.
- ESLint, Prettier, dan typecheck di frontend maupun backend.
- Pipeline CI menjalankan semua cek di setiap perubahan, lalu membangun image produksi dan memindainya dengan **Trivy**.
